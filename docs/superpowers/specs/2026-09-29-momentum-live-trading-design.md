# 모멘텀 결합 50:50 실거래 설계 (2026-10-06부터 펀딩 캐리 50% 편입)

## 배경

일봉 백테스트(2020-06 ~ 2026-09, 56개 코인, 수수료·펀딩 반영)에서 듀얼 모멘텀 + 시계열 모멘텀을 각각 포트폴리오
변동성 30%로 타게팅한 뒤 자본 50:50으로 결합한 전략이 Sharpe 1.16, 최대낙폭 -31%였다. 시드 2,000 USDT에서
거래소 최소 주문 제약을 반영한 복리 시뮬레이션도 제약 없는 경우와 거의 같았다(연 28%, 최대낙폭 -31%).
이 전략을 바이낸스 USDT-M 선물 실계좌에서 하루 1회 운용한다.

### 실거래 규칙으로 다시 잰 백테스트 (리밸런싱을 달력 기준 목요일로 바꾼 뒤)

| | Sharpe | 연평균 수익 | 최대낙폭 |
|---|---|---|---|
| 결합 50:50 (목요일, 실거래 규칙) | 1.28 | 30.5% | -31.5% |
| 리밸런싱 요일 7개 평균 (범위) | 1.22 (1.15~1.28) | 28.9% (27.3~30.4%) | -31.8% (-34.9~-30.0%) |

요일에 따라 Sharpe가 ±0.07 움직인다. 목요일은 결과를 보고 고른 값이 아니므로(1970-01-01 기준), 기대치는
요일 평균(Sharpe 약 1.2)으로 잡는다. 과거 성과는 미래를 보장하지 않는다.

### 코인 목록 검증 (2026-09-30) — 기대치 하향

고정 56개는 "2020년 말 이전 상장 + 지금도 거래 중"이라, 뒤 조건이 미래 정보다. 상장 폐지 코인까지 포함한
data.binance.vision 데이터(679개, 폐지 154개)로 2021-01 ~ 2026-08을 다시 쟀다 (규칙과 판단 기준은 실행 전에 정함).

| 목록 | Sharpe | 연평균 수익 | 최대낙폭 |
|---|---|---|---|
| 고정 56개 | 0.98 | 22.4% | -35.1% |
| 2020년 말 이전 상장 코호트 80개 (이후 폐지 20개 포함, 미래 정보 없음) | 0.94 | 21.3% | -35.5% |
| 매달 거래대금 상위 50 (상장 1년 이상) | 0.27 | 6.0% | -39.2% |
| 매달 상장 3년 이상 전부 (2023~, 같은 기간 고정 56개는 1.09) | 0.46 | 10.0% | -36.2% |

- 고정 56개의 우위는 미래 정보(생존) 탓이 아니다 — 폐지 코인을 넣은 같은 코호트도 0.94
- 우위는 "일찍 선물에 상장된 기성 코인" 코호트에서 나온다. 2021년 이후 상장 코인은 상장 후 3년이 지나도 이 전략에 맞지 않았다
- 따라서 고정 56개를 유지하되, 기대치는 2021년 이후 기준 **Sharpe 약 0.9~1.0, 연 약 21%, 최대낙폭 약 -35%**로 잡는다
  (2020년 하반기 상승장을 포함한 1.2는 낙관적). 최근(2025~2026) 성과는 약하다
- 한 번의 코호트·한 시기의 결과이며, 이 코인들이 앞으로도 추세를 잘 탈지는 보장되지 않는다

두 기간 마이너스면 청산). 새 파라미터 없음. `strategies.momentum.LIVE_OPTIONS`로 실거래·검증이 같은 설정을 쓴다.

### 시계열 엔진 숏 채택 (2026-09-30)

숏 변형 3개를 실행 전에 고정해 비교했다 (`uv run python -m alpha.backtest.momentum --shorts`). 시계열 엔진에만 숏을 추가:
세 기간 모두 마이너스면 숏 진입, 두 기간 마이너스면 1/3, 플러스로 돌면 청산 (롱의 거울상). 듀얼은 롱 전용 유지.
롱/숏 비율은 코인별 추세 신호가 정한다 (고정 비율·상한 없음).

| | Sharpe | 연평균 수익 | 최대낙폭 |
|---|---|---|---|
| 롱 전용 (고정 56개, 2020-06~) | 1.32 | 29.7% | -30.1% |
| **시계열 숏 (고정 56개, 2020-06~)** | **1.34** | 28.2% | **-23.1%** |
| 롱 전용 (2020년 이전 상장 코호트·폐지 포함, 2021~) | 1.02 | 21.8% | -31.5% |
| **시계열 숏 (같은 코호트, 2021~)** | **1.10** | 21.8% | **-23.0%** |

- 거래대금 상위 50(폐지·신규 포함)에서도 개선 (0.36 → 0.42, 최대낙폭 -36.5% → -28.4%)
- 숏의 가격 손익은 거의 0 (연 -1.1% ~ +0.7%) — 수익원이 아니라 하락장 보험. 2022년 -23% → -15%, 상승장 수익은 줄어든다
- 평균 노출 롱 27% / 숏 11%, 숏이 롱보다 큰 날 27%, 총노출 최대 1.11배. 2022년엔 순노출 -3%까지 중립화
- 듀얼 숏(하위 20% 숏)과 BTC 하락장 한정 숏은 기각 (숏 스퀴즈로 Sharpe 하락)
- 최근 300일로 계산한 비중 = 전체 기록 (실데이터 20개 날짜에서 차이 5e-15)
- 숏 위험: 손실 한도 없음, 숏 스퀴즈, 하락장에서 펀딩비가 마이너스면 숏이 낸다 (백테스트에 반영)
- **실거래 기대치: 2021년 이후 코호트 기준 Sharpe 약 1.1, 연 약 22%, 최대낙폭 약 -23%**

### 잔차 모멘텀 검토: 보류 (2026-11-02)

크립토 코인 간 시장 베타 착시를 줄이기 위해 그날 거래 목록 내 코인들의 동일가중 시장 수익률에 대한 60일 베타 성분을 뺀 잔차 수익률 $\epsilon_{i,t}$와 복리 잔차 $\log(1 + \epsilon_{i,t})$를 쓰는 사후 변형(`S4`, `residual=True`)을 검토했다 (`uv run python -m alpha.backtest.momentum --shorts`로 아래 표 전체 재현).
- **듀얼(횡단면 선정)**: 룩백별 복리 잔차 합 ÷ 잔차 변동성(정보비율) 순위로 상위 20% 선정 후 절대 추세 확인(`confirmed`) 필터 적용
- **시계열 엔진**: 원가격 시계열 비중과 복리 잔차 시계열 비중을 50:50 혼합
- **U3 목록 및 시장 정의**:
  - 모멘텀 U3 목록(`dynamic`): 상장 1년 이상 코인 중 매달 첫날 직전 30일 평균 거래대금(`quote_volume`) 상위 50개
  - 캐리 U3 목록: `funding_carry.py` 기본 정의는 매일 갱신되는 30일 평균 거래대금 상위 60개(`top60`)이며, 모멘텀과 동일하게 월간 상위 50개(`dynamic`)로 맞춘 결합도 함께 비교한다
  - 시장 수익률 정의: `universe`가 주어지면 `residual_returns`의 시장 수익률은 그날 `universe` 안의 코인(U3는 월간 상위 50개)만으로 계산해야 실거래(거래 목록 56개만으로 계산)와 정합적이다. 수정 전 초기 실험에서는 `universe`를 넘기지 않아 전체 679개 코인 평균으로 시장을 계산했다

#### 3) 통계·리스크 감사 요약 및 보류 사유 (출처: 2026-11-02 독립 감사 보고서)

- **보류 구간의 한계와 성과 역전**: `2025-10~` 보류 구간은 이전 모멘텀·캐리 연구에서 이미 여러 번 조회한 구간이므로 엄밀한 표본 외(out-of-sample) 검증이 아니다. 그 구간에서조차 U1·U2는 모멘텀 단독(`1.99→1.76`, `1.76→1.72`)과 캐리 결합(`2.44→2.23`, `2.56→2.48`) 모두 `S4`가 `S1`보다 낮다.
- **U3 시장 정의 민감도 및 요일 강건성 부족**: U3의 초기 보류 개선(`0.39→0.73`)과 MDD 악화(`-28.4%→-30.4%`)는 시장을 전체 679개 코인으로 계산한 데서 나왔다. 시장을 U3 거래 목록(50개) 안으로 제한하면 모멘텀 보류 Sharpe는 `0.39→0.00`, 캐리(일간 상위 60) 결합 보류는 `0.44→0.27`, 캐리(월간 상위 50) 결합 보류는 `0.94→0.67`로 낮아진다. U3 리밸런싱 요일 7개 평균 보류 Sharpe도 `S1 0.11` vs `S4 -0.18`이며 7개 중 6개 요일에서 `S1`보다 나쁘다. 또한 U3 전체 구간 개선은 잔차 없이 원수익률을 변동성으로 나눈 순위만으로도 결합 Sharpe `1.18`이 재현되어 순수 잔차 효과로 보기 어렵다.
- **변동성 조정 MDD**: `S4`의 외견상 MDD 감소는 대부분 변동성 축소(모멘텀 상쇄로 인한 노출 감소)에서 비롯된다. 변동성을 `S1` 수준에 맞춰 스케일링하면 캐리 결합 MDD는 U1 `-13.9%→-15.3%`, U2 `-12.4%→-12.7%`로 개선이 없다.
- **베타 회귀 및 부트스트랩 유의성**: `S4 - S1` 일수익 차이를 시장에 회귀하면 결합 기준 연환산 알파는 U1 `-1.4% (t -0.8)`, U2 `-0.4% (t -0.2)`, U3 `+0.5% (t 0.3)`로 0에 가깝고, 시장 베타만 유의하게 감소한다(U1·U2 약 `-0.043, t ≈ -13`). `S4`를 `S1`과 시장에 동시 회귀한 알파는 U1 `+2.6% (t 1.7)`, U2 `+3.4% (t 2.6)`, U3 `+1.6% (t 1.1)`로 약한 양의 근거에 그친다. 결합 Sharpe 개선의 부트스트랩 95% 신뢰구간은 모두 0을 포함한다(`U1 +0.08 [p=0.29]`, `U2 +0.20 [p=0.10]`, `U3 +0.09 [p=0.21]`).
- **실계좌 2,000 USDT 시뮬레이션 (U1, 평가금액 고정, 현재 최소 주문 규칙)**: 결합 Sharpe `2.23→2.25`, 보류 Sharpe `2.45→2.33`, 연수익 `33.3%→28.6%`, MDD `-15.1%→-13.3%`로 실계좌 제약 하에서 Sharpe 이득이 거의 사라지며, 기존 `S1` 비중을 단순히 86%로 축소한 결과(연수익 `28.6%`, MDD 약 `-13.0%`)와 유사하다.
- **추가된 자유도와 대안 시장 정의 민감도**: 시계열 혼합비 `0.5`, 동일가중 시장 정의, 듀얼의 정보비율 정규화가 암묵적 자유도로 추가되었다. 시장을 `BTCUSDT`로 바꾸면 결합 Sharpe가 U1 `2.11`, U2 `2.04`로 기존 `S1`(`2.22`, `2.14`)보다 낮아진다.
- **리스크 측면의 장점과 코드 보존**: U1 결합 기준 시장 베타(`0.071→0.028`), 최악의 하루(`-7.1%→-5.5%`), 시장 `-7%` 이하 109일 손익 합계(`-55.3%→-5.8%`)는 개선되고, 300일 슬라이싱 일치(240일 이상 오차 `5.4e-15` 이내, 220일부터 불일치; `S1`은 200일도 일치)와 미래 데이터 절단 무결성도 통과했다. 따라서 `residual=True` 경로는 연구용으로 코드·테스트에 남기되, 실거래(`LIVE_OPTIONS`)는 기존 `S1`(`{"confirm_entry": True, "ts_short": True}`)을 유지한다.

## 펀딩 캐리 50% 편입 (2026-10-06)

평가금액의 50%를 횡단면 펀딩 캐리 롱숏(숏 스퀴즈 방어 포함, `strategies/carry.py`)에 배분한다 (사용자 결정, 권고는 30% 안팎).
근거·검증: `docs/superpowers/specs/2026-10-06-funding-carry-research.md`.

- 한 계좌에서 코인별 순비중으로 합친다: 목표 비중 = 0.5 × 모멘텀 결합 + 0.5 × 캐리 (`strategies/portfolio.py`).
  두 전략이 같은 56개 코인을 거래하고 단방향 모드라 별도 계정 없이 상쇄되며, 매일 실행 때마다 50:50으로 다시 맞춰진다
- 캐리는 주 1회(일요일 봉 = 월요일 00:05 UTC 실행) 종목을 고르고, 매일 실행 때 보유 숏의 스퀴즈 상태를 점검해 청산한다.
  같은 cron(매일 00:05 UTC)이 둘 다 처리한다
- 실거래와 같은 순비중 백테스트 (56개, 수수료·펀딩 반영):

| 구간 | 모멘텀만 | 모멘텀 50% + 캐리 50% |
|---|---|---|
| 전체 2020-06 ~ 2026-09 | Sharpe 1.34, 연 28.1%, MDD -23.1% | Sharpe 2.21, 연 33.4%, MDD -13.9% |
| 2022-01 ~ 2025-09 | 0.53 | 1.23 |
| 보류 2025-10 ~ 2026-09 | 1.99 | 2.44 |

- 총 노출 평균 0.61배, 최대 0.94배. 2,000 USDT에서 최소 주문 때문에 0이 되는 비중 평균 1.0% (최대 3.3%)
- **기대치는 낮춰 잡는다**: 캐리 수치는 지금 남아 있는 56개 기준이라 낙관적이고(거래대금 상위 60 동적 목록에서는 크게 약함),
  스퀴즈 방어는 개선안 12개 중 고른 것이다. 결합 기대 Sharpe 1.0 ~ 1.5 수준

## 결정 사항

- 전략: 결합 50:50 + 진입 확인 + 시계열 엔진 숏 (`strategies.momentum.combined_weights(closes, **LIVE_OPTIONS)`) — 백테스트와 같은 함수를 쓴다
- 2026-10-06부터: 위 모멘텀 50% + 펀딩 캐리 50% (`strategies.portfolio.live_weights`)
- 실행: 하루 1회 실행 스크립트 `python -m alpha.live.runner`, 매일 UTC 00:05(한국 09:05)에 스케줄러(cron)가 실행
- 가동 절차: 실계좌, dry-run 기간 없이 바로 실주문 (2026-09-30 결정). 서버 cron은 `--live`로 등록한다.
  실행기를 손으로 돌릴 때는 기본이 dry-run(계산·기록만)이라 `--live`가 없으면 주문이 나가지 않는다
- 주문: 시장가. 줄이는 주문을 먼저, 늘리는 주문을 나중에(증거금 확보)
- 계좌 설정: 단방향(one-way) 포지션 모드, 교차 증거금, 코인별 레버리지 설정 3배(증거금 여유용일 뿐 실제 노출은 전략 비중이 정함)

|---|---|

| `strategies/carry.py` | 펀딩 캐리 롱숏 + 숏 스퀴즈 방어 비중. 백테스트(`backtest/funding_carry.py`)와 공유 |
| `strategies/portfolio.py` | 모멘텀·캐리 몫을 합친 실거래 목표 비중 (`CARRY_SHARE = 0.5`) |
| `exchange/client.py` | 바이낸스 통신만: 마감된 일봉, 펀딩 이력, 거래 규칙(최소 금액·수량 단위), 마크 가격, 계좌 평가금액, 포지션, 시장가 주문, 계좌 설정 |

## 백테스트와 일치시키기 위한 규칙

- 횡단면 리밸런싱을 "데이터 첫 봉부터 7일마다"에서 **달력 기준(1970-01-01부터 7일마다, 즉 매주 목요일 봉)**으로
  바꾼다. 실거래는 최근 300일만 받으므로, 시작 봉 기준이면 백테스트와 다른 날 리밸런싱하게 된다.
  "최근 300일로 계산한 오늘 비중 = 전체 기록으로 계산한 오늘 비중"을 테스트로 보장한다.
- 캐리도 같다: 일봉 300일 + 펀딩 20일로 계산한 오늘 비중 = 전체 기록 비중 (실데이터 최대 차이 3e-15, `tests/test_carry.py`).
  캐리 리밸런싱은 일요일 봉(데이터와 무관한 달력 기준)
- 목표 비중은 방금 마감된 일봉 종가 기준, 주문 수량은 실행 시점 마크 가격 기준으로 계산한다.

## 주문 계산 규칙

- 목표 금액 = 비중 × 계좌 평가금액(지갑 잔고 + 미실현 손익)
- 거래소 최소 주문(최소 명목 금액, 최소 수량 × 가격 중 큰 값) 대비
  - 절반 미만이면 0(보유 안 함), 절반 이상 최소 미만이면 최소 금액으로 올림, 그 이상이면 그대로
- 목표 수량은 수량 단위로 0 방향 버림. 차이가 최소 주문 금액 미만이면 건너뛴다(단, 포지션을 0으로 정리하는 주문은 reduce-only로 낸다)
- 거래 불가(상장 폐지·거래 중지) 코인은 목표 0 — 보유 중이면 정리
- 다시 실행해도 목표와의 차이만 주문하므로 같은 날 재실행이 안전하다

## 안전장치

- dry-run 기본, `--live` 명시 시에만 주문
- 데이터 최신성: 모든 계산에 쓰는 마지막 봉이 어제(UTC) 봉이 아니면 중단
- 펀딩 최신성: 최근 하루 안 정산 기록이 있는 코인이 15개 미만이면 중단 (캐리 신호가 조용히 비는 것을 막는다)
- 총 목표 노출(|비중| 합)이 1.5배 초과, 주문 1건이 평가금액의 50% 초과면 중단 (전략상 나올 수 없는 값 — 버그 방지)
- 헤지 모드 계좌면 중단
- 주문 실패는 기록하고 나머지 주문을 계속한 뒤 종료 코드 1로 알린다

## 운용 절차

1. 바이낸스에서 API 키 발급: 선물 거래 권한만, 출금 권한 없음, IP 제한. `.env`의 `BINANCE_API_KEY`, `BINANCE_API_SECRET`에 저장
2. 텔레그램 보고 설정 (`live/notify.py`): @BotFather에서 봇을 만들어 토큰을 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣고,
   봇에게 아무 메시지나 보낸 뒤 `uv run python -m alpha.live.notify --chat-id`로 채팅 ID를 확인해 `TELEGRAM_CHAT_ID`에 넣는다.
   `uv run python -m alpha.live.notify --test`로 확인. 매 실행(dry-run 포함) 후 잔고·전일/누적 손익·진입·청산(손익)·조정·보유 현황을
   보내고, 실행이 실패하거나 안전장치로 중단되면 경고를 보낸다. 누적 손익은 같은 모드의 첫 실행 잔고 기준이라 입출금이 섞인다
3. `uv run python -m alpha.live.runner --setup` — 교차 증거금·레버리지 3배 설정 (한 번)
4. (선택) `uv run python -m alpha.live.runner` — 주문 없이 목표·주문 목록만 확인
5. `uv run python -m alpha.live.runner --live` — 바로 시작하려면 수동 실행, 아니면 다음 09:05 cron이 첫 실주문
6. 텔레그램 조회 봇 (`live/bot.py`, 상시 실행): `deploy/alpha-bot.service`를 systemd에 등록한다.
   명령 /balance /positions /pnl /last /status /help, 설정된 채팅에만 응답, 조회 전용(주문 없음). 매매 실행기와 별도 프로세스라
   봇이 죽어도 매매에는 영향이 없다. `notify --chat-id`는 봇을 켜기 전에 실행할 것 (둘 다 getUpdates를 써서 충돌)
7. cron 등록: `5 0 * * * cd <프로젝트> && uv run python -m alpha.live.runner --live >> logs/live/cron.log 2>&1` (UTC 기준)

## EC2 배포

`deploy/setup_ec2.sh` (Ubuntu 24.04, x86_64, 도쿄 리전, Elastic IP). 여러 번 실행해도 안전하고, 준비가 필요한 단계에서 멈춘다:
패키지·UTC → uv → GitHub 배포 키(읽기 전용) → 저장소·의존성 → .env(chmod 600) → 조회 봇 systemd →
바이낸스 연결 확인(주문 없음: 잔고·단방향 모드, 공인 IP 출력) → 계좌 설정(`runner --setup`) → 매매 cron(실주문) → 텔레그램 테스트.
코드 갱신도 같은 스크립트를 다시 실행한다.
